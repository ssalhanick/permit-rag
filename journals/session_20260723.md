## Findings worth keeping

1. **Reranker-rejected chunks were being prompted and billed.** `reranker.py:100`
   marks them `filtered_out=True` and `retriever.py:243` exposes `passing_chunks`
   for exactly this, but `query.py:423` passed `result.chunks`. Fixed inside
   `generate_answer` so the eval harnesses (`ragas_eval.py:652`,
   `langsmith_eval.py:123`) get it too — they had the same bug, meaning evals were
   scoring a different chunk set than intended.
2. **`GenerationResult` discarded its cache token counts.** They were computed at
   `generator.py:464`, logged, and thrown away — so cache effectiveness, a headline
   metric of the plan, was unmeasurable. Now carried on the dataclass under the
   Anthropic field names.
3. **Two sprint8 tests were failing before this session.** `MagicMock.__iter__`
   returns an *empty* iterator while the attribute itself is truthy, so
   `body.chunk_ids` sent the route down the by-id branch and the patched retrieval
   never ran. They also patched `api.routes.query.retrieve`, which `/query/answer`
   does not call — it calls `retrieve_with_project`. Both fixed.
4. **`_extract_citations` keeps unverifiable citations**, flagged
   `found_in_context=False`, and nothing currently blocks them from reaching the
   user. Pre-existing and left alone — that is the Citation Verifier's job (agent
   #9, Phase 5). Documented in the test.
5. **Sonnet 5 intro pricing is live** ($2/$10 vs $3/$15 through 2026-08-31), so
   real spend today is ~⅓ below the plan's list-price table. Encoded with an
   expiry date so it self-corrects on 2026-09-01.
6. **Dedupe bug caught by a rolled-back dry run of migration 026.** The action
   queue's unique index covered nullable `entity_type`/`entity_id`, and NULLs
   never conflict in a unique index — so any entity-less item (exactly what a
   scheduled anomaly sweep files) skipped dedupe silently: 2 rows from 2 upserts.
   Fixed by making both columns `NOT NULL DEFAULT ''`. An expression index over
   `COALESCE()` was tried first and rejected: Postgres cannot infer a *partial*
   index from an expression `ON CONFLICT` (`InvalidColumnReference`).
   **This is the argument for verifying before deploying** — AGENTS.md freezes a
   migration once deployed, so applying 026 to prod first would have required a
   027 to correct it.

## Verification performed

Migration 026 was dry-run against local Docker Postgres inside
`conn.transaction(force_rollback=True)` — nothing persisted. Confirmed: all five
tables create, 15 autonomy ceilings seed, entity-bearing dedupe collapses 3
upserts to 1 row, entity-less dedupe collapses 2 to 1, distinct entities stay
separate, and a resolved item can be legitimately re-raised.

## Decisions

| Decision | Choice |
|----------|--------|
| Structured outputs | Native `client.messages.parse()`, not `instructor` — pydantic is already a dep |
| Trace table types | `text` + `CHECK`, not enums — new agent names never need `ALTER TYPE` |
| Tracing failure mode | Degrade to a log line, never raise |
| Autonomy ceilings | Clamped in SQL *and* the runtime; dashboard cannot raise them |
| Persona default | `research`, never `diy` |
| Run scope on the route | Decorator, not a `with` block — avoids a 377-line reindent |
