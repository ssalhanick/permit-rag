## What was accomplished

### `rag/agent_runtime.py` — the single Anthropic call site
- `run_agent(...)` owns, in one place: `messages.parse` structured outputs
  (→ `.parsed_output`) vs. `messages.create` text; the cheap/mid/top model
  ladder (`Tier(StrEnum)`); `output_config` effort; measured prompt caching;
  `count_tokens` budgeting; automatic tracing; autonomy enforcement; retries.
- **Caching that refuses the silent-no-cache footgun.** The runtime counts the
  request once with `count_tokens` and attaches a `cache_control` breakpoint to
  the system block *only* when it clears the model minimum (4096 haiku/opus,
  2048 sonnet). Below that it sends a plain string. A single `count_tokens` call
  serves both the budget check and the cache decision — no double round-trip.
- **Autonomy is enforced here, fail-closed.** `resolve_autonomy_level` returns
  L0 for any agent absent from `agent_autonomy`, and clamps a stored level to
  `max_level` on read (belt-and-suspenders over the SQL clamp).
  `enforce_autonomy` is the primitive future action-agents call before a side
  effect; `run_agent(required_autonomy=...)` can gate the call itself, and every
  step records the resolved level regardless.
- Retries back off on the transient Anthropic error classes only (rate-limit,
  connection, timeout, 5xx, overloaded) — a 4xx is not retried.
- Decomposed into `_dispatch` / `_finish` / `_system_payload` / `_count_tokens`
  helpers to keep every function within the 50-line rule.

### `rag/agents/` — the registry
- `registry.py`: frozen `AgentSpec` dataclass + a `runtime_checkable`
  `AgentSpecProtocol`; `register` (raises on duplicate unless `replace=True`),
  `get`/`get_or_none`/`all_specs`/`names`/`clear`. `lazy(module, attr)` returns a
  proxy that imports on first call.
- `__init__.py`: rag self-registers `answer_generator` and `design_intent` on
  import, both lazily bound — so importing `rag.agents` pulls in **neither**
  `rag.generator` nor `sentence_transformers` (verified: 0.31s, deps absent).
- Import boundary held: registry imports nothing from commerce/forms/bids; a
  test greps the source to prove it. `api/main.py` will inject those agents.

### `rag/design_intent.py` — folded into the runtime
- `_parse_design_intent_llm` now calls `run_agent` with a `DesignIntentParse`
  pydantic schema (`OverlayPatch` with `extra="allow"`), so overlays are
  schema-valid by construction. The `@traced` decorator was removed — the
  runtime records the step now, so keeping it would double-count.
- Public contract unchanged: still returns `{overlays, explanation, usage}`;
  usage is read off `RuntimeResult.usage`. `test_room_design_intent.py` green.

## Findings worth keeping

1. **`anthropic==0.116.0` supports everything the plan assumed.** `messages.parse`
   takes `output_format` + `output_config`; `ParsedMessage.parsed_output` is the
   attribute; `messages.create` and `count_tokens` both accept `output_config`
   and `system`. No SDK bump needed (`pyproject` pins `>=0.25.0`).
2. **One `count_tokens` call covers both budget and cache decision.** Earlier
   worry about a double round-trip was unfounded — `caches_ok` is derived from
   the same counted value used for the budget check.
3. **On a `count_tokens` failure the runtime skips both budgeting and caching**
   rather than guessing (no tiktoken fallback). Skipping caching is the safe
   direction — attaching a breakpoint to an unmeasured block risks a silent
   no-op; not attaching just forgoes a cache hit.
4. **Prod 027 status is genuinely ambiguous** between STATE and the 07-23
   journal. Left as a punch item with a check-first command — a `NOT NULL` alter
   is not safe to blind-re-apply.
5. **The SDK version differs between machines, and the retry list broke on it.**
   `verify_phase1.py` failed on the corpus machine with
   `AttributeError: module 'anthropic' has no attribute 'OverloadedError'`.
   `_retryable_errors()` runs on *every* call (not just on failure), so this hit
   the success path too. Fixed by resolving the names via `getattr` and falling
   back to `anthropic.APIError`.
6. **Prod runs anthropic 0.104.1, and it supports everything Phase 1 needs.**
   Verified by installing that exact version in a throwaway venv and
   introspecting: `messages.parse` accepts `output_format` + `output_config`,
   `ParsedMessage.parsed_output` exists, `count_tokens` exists,
   `RateLimitError` / `InternalServerError` / `APIError` exist — only
   `OverloadedError` is missing. So the design_intent structured-output fold is
   safe on prod.
7. **`pyproject.toml` pinned `anthropic>=0.25.0`** — far below the floor the
   runtime needs (0.25 predates `messages.parse`). A fresh Docker build could
   have resolved a version where design_intent fails at runtime with an
   `AttributeError` instead of failing at build time. Raised to `>=0.104.1`,
   the version verified on prod.
