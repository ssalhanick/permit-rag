### Prompt formatting fix + RAGAs investigation (`PROMPT_VERSION` v1 → v3)
User reported a real prod bug via screenshot: a "Key considerations" answer
rendered as `• Foundation Assessment: ... • Code Compliance: ...` all inline
in one paragraph instead of a real list. Root cause: both prompt paths said
"use bullet points" without specifying markdown syntax, so the model
sometimes used inline `•` characters instead of `- ` on separate lines —
`ReactMarkdown` was rendering exactly what it was given; not a rendering bug.

- **v2** — rule 7 (both `rag/generator.py`'s `SYSTEM_PROMPT` and
  `rag/prompts/fragments/base.md`, shared by every persona) now requires
  real markdown lists, forbids inline `•`. Verified: 67 relevant tests green,
  no new ruff issues (only the 2 pre-existing en-dash `RUF001` hits, which
  STATE.md already says never to "fix" — live prompt text, would perturb the
  RAGAs baseline).
- **RAGAs regression found on verification.** First live run (`--no-answer-cache`)
  post-v2: avg faithfulness 0.792, avg relevancy 0.678 — two queries (q0, q4)
  scored *exactly* 0.000 relevancy. Re-run: q0 recovered to 0.989 (judge
  noise), but **q4 stayed at 0.000 both times** despite its other metrics
  moving around — the one reproducible signal.
- **A/B isolation.** Same-day control run against `v1` (temporarily restored
  via `git checkout <parent-of-fix-commit> -- rag/generator.py
  rag/prompts/fragments/base.md`, then reverted): q4 scored **1.000**
  relevancy under `v1`. Clean same-day, same-corpus comparison — confirms
  the regression is edit-caused, not day/corpus variance (which faithfulness
  was: `v1`-today's 0.770 avg was *lower* than both `v2` runs, so that
  overall dip is environmental, unrelated to the edit).
- **v3 attempt.** Read q4's actual answer text: well-grounded, correctly
  cited, but closed with a standalone **"Limitation"** header explicitly
  telling the user to consult the City of Plano directly. Hypothesized the
  new rule 7's push toward discrete markdown blocks spilled over into
  promoting the existing uncertainty rule (rule 1) into its own header.
  Rewrote rule 1 to forbid a standalone header, keep the caveat inline.
  Bumped to `v3` (`base.md` → version 3). **Did not fix it** — q4 still
  scored 0.000. The header was genuinely gone from the new answer text
  (confirmed by reading it), proving the header was never the mechanism.
- **Root cause, final.** The redirect sentence itself — "you should contact
  the City of Plano Building Inspection Department directly" — is what
  RAGAs' `answer_relevancy` metric hard-zeroes as noncommittal, header or
  not. That sentence is the same pattern as this app's existing
  `_AHJ_DISCLAIMER_TEXT` — intentional caution for a compliance app on a
  genuinely under-covered broad query, not a hedge to prompt away.
  **Decision: stop chasing it.** Recorded in STATE's Decisions log as a
  known judge blind spot, same treatment as q6 in the original 2026-07-25
  baseline — measure, don't gate, on this one query's relevancy score.
  `v3` ships as-is: it fixed the real inline-bullet prod bug, faithfulness
  was flat-to-better across every edited run, and the one regression has an
  explained, low-stakes, non-quality cause.
