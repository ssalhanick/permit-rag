### Phase 0 — document security fix (confirmed vulnerability, not just a UX gap)
Two real problems, not the "should users see the document corpus" UX
question Scott's list originally framed this as:
1. `GET /api/documents` had **no auth dependency at all** — reachable by
   anyone, authenticated or not, returning the full corpus including other
   users' pending petitions and private project documents.
2. `match_chunks` (the general RAG retrieval path) never filtered on the
   `visibility` column migration 040 added specifically for this — its own
   header comment says retrieval "must filter `visibility='team'` OR
   `uploaded_by=<user>`," never implemented. **Confirmed**: another user's
   private project document could surface verbatim in your chat answer.
   The Python-level plumbing for this mostly already existed
   (`requesting_user_id` threaded from `api/routes/query.py` through
   `manager.py`, already correctly used by the project-scoped mini-RAG path,
   `match_project_chunks`) — someone had built 90% of the fix and never
   finished the last three hops (`retrieve_with_project` → `retrieve()` →
   `match_chunks()`). New migration `045_match_chunks_visibility.sql` +
   matching `db/client.py`/`rag/retriever.py` changes close it.
   **Code-complete, mocked-tests-green, NOT RAGAs-verified** — see STATE.md
   punch list.

Fixed:
- Auth-gated `GET /api/documents`, `GET /api/documents/{doc_id}`,
  `GET /api/documents/status`. Bulk listing (`GET /documents`) is
  **superadmin-only** ("only super users see the document corpus" was an
  explicit product call); single-doc lookup by doc_id stays on the broader
  staff bypass (a citation drill-down already implies the doc_id is known).
- New `db_client.list_documents_for_user()` — a regular user's own scoped
  "Document Library" (owned or team-shared tier-3 docs only).
- New `GET /documents/{doc_id}/download` (auth + same visibility check,
  files weren't downloadable via the API at all before).
- Rebuilt `ProfileDocumentsPage.jsx` into a real Document Library — it was
  double-broken before this (fetched the full unscoped corpus, tried to
  filter client-side on `uploaded_by`, which the API response never
  included, so regular users saw an empty library while any admin-role
  account saw literally everything). Four actions: view/download, delete
  own upload (existing `delete_project_document` endpoint, just never had a
  frontend caller), replace/re-upload (new
  `POST /projects/{id}/documents/upload/{doc_id}/replace`, supersedes via
  the existing `db_client.supersede_document` — never a hard delete, per
  AGENTS.md Document Governance Rules), review-status badge.
- New staff petition-review UI (`PetitionReviewPane.jsx`, new "Petition
  Review" tab on `/admin/agents`) — the approve/reject backend for both
  ordinance petitions and overlay petitions already existed and was already
  properly gated; there was zero frontend, review was curl/Postman only.
- Frontend `/documents` route (the corpus browser) gated behind
  `SuperadminRoute` to match; fixed two now-dead links on
  `ProjectDocumentsPage.jsx` that pointed at it.
- 15 new backend tests (`test_documents_routes.py`,
  `test_retriever.py`, `test_project_documents.py`) covering the auth gate,
  tier-3 visibility scoping (private/team/owner/non-member), the
  `requesting_user_id` threading regression specifically, and the
  replace-endpoint's artifact-vs-chunkable ordering.

### Phase 1 — isolated bug fixes
- **Project name sticky-default** — going back to the address step and
  changing it never updated the auto-derived project name once it had been
  set once (`w.name || suggested` guard). Now keyed off a `nameManuallyEdited`
  flag, set only when the user actually types into the field (or when
  resuming a project that already has a real saved name).
- **Project switcher silently not switching** — `ProjectSwitcher.jsx` passed
  the whole project object where the backend PATCH expects a plain id
  string; fixed, plus a bonus bug found in passing: reloading a past query
  from `ProjectQueriesPage.jsx` navigated to `/?...` instead of `/query?...`,
  landing on the auth-redirect root and silently discarding the reload.
- **Learn More button invisible in light mode** — hardcoded
  `color: #f8fafc` unscoped to `.dark`, which is exactly the light-mode
  `--background` value; text and background were the same hex.
- **"+ Add Task" wrapping at the +** — `tt-btn-add-task-inline` was
  referenced in JSX but never defined in any stylesheet (zero layout
  rules). Same root-cause pattern turned up again in Phase 3. Also added a
  big "Add Task" CTA for the empty task-list state.
- **`/welcome` route** — signed-in users hitting `/` always redirected to
  `/dashboard` with no way back to the marketing page; added an
  always-reachable `/welcome` route, made the landing page's CTAs
  auth-aware ("Go to Dashboard" instead of "Get Started"), and pointed the
  nav logo there when signed in (it used to link to `/`, which was a dead
  click while authenticated).
- **Icon audit** — turned out much smaller than feared: 88 icons across 29
  files, all `lucide-react`, one leak (`@hugeicons` confined to the shared
  `Select` primitive). Swapped 4 icons, removed the now-fully-unused
  `@hugeicons/*` packages from `package.json`.

### Phase 2 — voice input consolidated into one hook
5 independent copy-pasted implementations (kickoff form fields, kickoff
chat, compliance assistant, debug page, room design), each drifted into a
different subset of bugs — confirmed the actual mechanism: `RoomCaptureWeb.js`
emitted two different strings for the same "no speech" condition (`"no-speech"`
from the real `onerror` event, `"No speech detected"` from a synthesized
`onend` fallback) and each call site only ever checked one of the two forms.
No paid/rate-limited STT anywhere — Scott's "free-tier throttling" theory was
a red herring; it's the browser's native Web Speech API, unthrottled.

New `frontend/src/hooks/useVoiceInput.js` owns the state machine (fixes the
compliance-assistant mic icon being hardcoded blue with zero listening-state
binding) and one error-mapping table (fixes the self-contradictory
"Voice input not supported: no speech detected" wording). Migrated
`QueryPage`, `DebugQueryPage`, `ProjectKickoffPage`'s `VoiceTextarea`, and
(separate `[ROOMSCAN]` commit) `RoomDesignPage`. Removed one genuinely dead
handler along the way (`ProjectKickoffPage`'s kickoff-chat voice handler had
no button wired to it anywhere — never reachable).

### Phase 4 — superadmin project visibility
Backend RBAC already existed (`is_staff`/`is_superadmin`,
`list_all_projects()` for staff) — staff already got every user's projects
blended into their list, just with no visual distinction and no owner
identity. Added `owner_username`/`owner_email` to `list_all_projects()`'s
join (staff-only path; the member-scoped query still omits it). Unified two
inconsistent frontend superadmin checks (`Nav.jsx` checked
`role === "superadmin" || is_superadmin`; `SuperadminRoute.jsx` checked only
`role !== "superadmin"`) into one `useIsSuperAdmin()` hook. Dashboard
project grid + nav `ProjectSwitcher` both render another user's project
fully inert for a superadmin viewer — visible, owner name, lock icon, not
clickable — confirmed directly with Scott that "disabled" meant literally
inert, not a read-only detail view.

### Phase 5 — mic-permission-denied instructions
No browser exposes a URL a page can navigate to for its own per-origin
permission settings (blocked cross-browser for anti-abuse reasons) — the
deep link Scott originally asked for isn't achievable. Built the actual
achievable version: `MicPermissionHelp.jsx` detects the browser and shows
the exact click-path, wired through `useVoiceInput`'s `errorCode`.

### Phase 6 — kickoff entry redesign + free-form extraction
"Continue an existing project" shrunk to a plain link (was a full card, same
visual weight as "Start a new project"). "Start a new project" now opens a
sub-choice screen — fill out a form / free-form text / free-form talk — 
instead of jumping straight into the step wizard. Free-form text/talk both
feed a new `POST /projects/kickoff/extract` endpoint
(`generate_kickoff_extraction` in `rag/generator.py`, same
`run_agent()`/`Tier.CHEAP` pattern and `bound_notes()` injection-surface
discipline as the existing kickoff chat) that extracts a best-effort guess
across address/spaces/work_types/materials/budget/persona — confirmed
directly with Scott that this **pre-fills the existing wizard for review**,
it does not bypass it or create a project directly. `address_guess` is
plain text, not geocoded; the user still picks a real `AddressAutocomplete`
suggestion.

Caught a real bug while wiring the merge: `SPACE_OPTIONS` is a grouped
`{indoor, outdoor}` object, not a flat array `splitKnownAndOther` could use
directly (`.includes` would have thrown at runtime the first time this path
ran) — exported the already-correct flattened `ALL_SPACE_OPTIONS` from
`projectKickoffRoutes.js` instead of re-deriving it. Also added
`canonicalizeLabels()` — an LLM's lowercase guess ("kitchen") needs to
case-insensitively match the wizard's Title-Case checkbox options
("Kitchen") or everything silently falls into free-text "other" instead of
a checked box.

### Follow-up: missing feedback buttons (Scott's item #7, re-raised)
Scott reported not seeing the thumbs-up/down feedback controls that already
exist on every answer. Real explanation, not a discoverability issue: the
controls are gated on `turn.run_id` being present
(`QueryPage.jsx`), and `audit/logger.py`'s `start_run()` deliberately lets a
request succeed **untraced** if opening the trace row fails — "tracing must
not break the request" — so `run_id` can legitimately be `None` on rare
occasions. The row used to just silently vanish in that case, reading as the
feature being missing rather than unavailable for that one response. Now
shows "Feedback isn't available for this response" instead.
